# Strict Guardian Profile Separation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make learner mode learner-only, present guardian entry as a password-locked gateway instead of a peer profile tab, and place adult learner-detail editing under canonical Guardian routes.

**Architecture:** Keep the existing server-side guardian session and mutation guards. Change the shared account menu to an asymmetric learner gateway/guardian action menu, add `/guardian/profile` and `/guardian/profile/setup` as canonical aliases for the existing editor/setup views, and remove the unauthenticated private-preview level picker. Protect the result with accessible behavior tests and a locked deep-link matrix.

**Tech Stack:** React 19, React Router 7, TypeScript, Tailwind CSS 4, Node test runner with Vite SSR, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-25-strict-guardian-profile-separation-design.md`

## Global Constraints

- Learner mode contains no adult management controls and no Learner/Guardian segmented switch.
- `Grown-up access` is the only learner-side bridge and always requires the existing server-verified account password before management content renders.
- All adult profile editing generated by the app uses `/guardian/profile` or `/guardian/profile/setup?redo=1`.
- Existing `/profile` and `/profile/setup?redo=1` URLs remain guarded compatibility aliases.
- Initial `/profile/setup` onboarding remains learner-accessible.
- No new dependency, credential, PIN, persistence model, or duplicated control primitive.
- Tests use accessible locators and rendered behavior; they do not assert Tailwind classes.
